Level 3 / Advanced HTML

Make the browser work with you.

Explore modern browser features and the craft around production HTML: accessibility, meaningful metadata, robust fallbacks, and thoughtful performance.

Advanced means intentionalPrefer native HTML first. Add ARIA, JavaScript, and custom behavior only when they solve a real need and remain usable without a mouse.
01

HTML5 features

HTML5 brought a modern standard for the web's markup, including semantic page elements, native audio and video, richer form controls, and graphics with canvas and SVG. The standard continues to evolve, so HTML is not a frozen list of features.

Use built-in elements and browser behavior when they fit. Native controls often provide keyboard support and accessibility behavior without extra scripting.

02

Advanced form elements

Group related controls with <fieldset> and describe the group with <legend>. Elements such as <output>, <progress>, and <meter> communicate calculated results, task progress, and measurements. 

<fieldset>
  <legend>Shipping address</legend>
  <label for="postal-code">Postal code</label>
  <input id="postal-code" name="postal-code" autocomplete="postal-code">
</fieldset>
<label for="upload-progress">Upload progress</label>
<progress id="upload-progress" value="3" max="5">3 of 5</progress>

A progress element needs a changing value to reflect real progress. A meter is for a known range, such as disk usage, not an in-progress task.

03

<datalist>, <details>, <summary>, <dialog>

<datalist> suggests values for an input without limiting the user to those options. <details> creates a disclosure region; its first child <summary> is the visible label. A <dialog> can show a modal or non-modal dialog. 

<label for="city">City</label>
<input id="city" list="cities">
<datalist id="cities">
  <option value="Toronto">
  <option value="Vancouver">
</datalist>

<details>
  <summary>Shipping details</summary>
  <p>Orders ship in two business days.</p>
</details>

<dialog id="notice">Saved successfully.</dialog>
<!-- JavaScript can call notice.showModal() and notice.close(). -->

Use dialog methods instead of adding open for a modal. When opening one with JavaScript, manage focus and provide a clear way to close it.

04

<figure> and <figcaption>

Use <figure> for self-contained content that is referenced from the main text, such as a photo, diagram, or code sample. A <figcaption> gives that content a caption. 

<figure>
  <img src="images/seedlings.jpg"
    alt="Seedlings growing in a tray">
  <figcaption>Seedlings, two weeks after planting.</figcaption>
</figure>
05

<picture> and responsive images

<picture> lets the browser choose among alternate image files, often by format or viewport width. Put one or more <source> elements before a fallback <img>. The alt text belongs on that <img>. 

<picture>
  <source srcset="images/plant-wide.webp" media="(min-width: 800px)">
  <source srcset="images/plant-small.webp" type="image/webp">
  <img src="images/plant-small.jpg"
    alt="A young tomato plant beside a window"
    width="640" height="480">
</picture>

For the same image at different resolutions, srcset and sizes on <img> let the browser choose an appropriate file. Include width and height to reserve space while it loads.

06

<source> and media formats

<source> provides alternative files inside <picture>, <audio>, or <video>. Use accurate MIME types so the browser can decide what it supports. Offer a broadly supported fallback where practical. 

<video controls width="640">
  <source src="media/demo.webm" type="video/webm">
  <source src="media/demo.mp4" type="video/mp4">
  Your browser does not support this video.
</video>

Choose formats based on your audience and media pipeline, and provide captions or transcripts when the content needs them.

07

Meta tags

Metadata belongs in <head>. It describes the document to browsers, search engines, and link previews; it is not a substitute for clear page content. 

<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<meta name="description"
  content="A practical guide to growing herbs at home.">
<meta property="og:title" content="The Small Garden">

Write a distinct, accurate title and description for each page. Social preview metadata such as Open Graph can control the title, description, and image shown when a page is shared.

08

SEO-friendly HTML structure

Help search engines and readers understand the page: use a specific <title>, a useful main heading, descriptive link text, meaningful section headings, and semantic HTML. Keep important content available as text, and use accurate image alternatives. 

<main>
  <article>
    <h1>How to grow basil indoors</h1>
    <p>Start with a sunny window and well-drained soil...</p>
    <h2>Choose a container</h2>
    <!-- Helpful, crawlable links and relevant images go here. -->
  </article>
</main>

There is no guaranteed ranking from a particular tag. Prioritize helpful content, accurate metadata, accessible structure, and fast, usable pages.

09

Accessibility and ARIA basics

Start with semantic HTML: native buttons, labels, headings, and landmarks already expose useful roles and behavior. ARIA can add accessible names or states when native HTML does not express them, but it does not add behavior by itself. 

<button type="button" aria-expanded="false"
  aria-controls="account-menu">Account</button>
<nav id="account-menu" hidden>...</nav>

If JavaScript opens the menu, it must also update aria-expanded, show the controlled content, and support keyboard interaction. Keep ARIA state in sync with the interface.

A useful rule: no ARIA is better than incorrect ARIA. Test with keyboard and assistive technology, not only by inspecting attributes.

10

Keyboard accessibility

Every interactive feature should work without a mouse. Use native links and buttons, keep focus visible, follow a sensible document order, and avoid positive tabindex values that force a confusing custom sequence. 

/* Keep keyboard focus visible. */
:focus-visible {
  outline: 3px solid #24584d;
  outline-offset: 3px;
}

<!-- A skip link lets keyboard users bypass repeated navigation. -->
<a class="skip-link" href="#main-content">Skip to content</a>

Check that Tab and Shift+Tab reach controls in a logical order, Enter activates links and buttons, and Escape closes appropriate dialogs. Never remove the focus outline without a clear replacement.

11

HTML validation

Validation checks markup against HTML syntax rules and catches mistakes such as mismatched tags, invalid nesting, and duplicate IDs. Validate during development, then separately test behavior and accessibility.

Use the Nu HTML Checker or a validator built into your editor. For local projects, validate the saved file or paste a small example into the checker. Fix errors first, then review warnings with context.

Valid markup is valuable, but it does not guarantee accessible, secure, or well-designed behavior.

12

Structured data / Schema.org basics

Structured data describes a page's entities in a machine-readable format. Schema.org defines shared types and properties. JSON-LD is commonly placed in a script element in the document head or body. 

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Person",
  "name": "Alex Rivera",
  "url": "https://example.com/"
}
</script>

Only describe information that is actually visible and accurate on the page. Structured data may make a page eligible for certain search features; it does not guarantee a rich result or higher ranking.

13

Web storage basics

localStorage keeps string values for an origin across browser sessions. sessionStorage is scoped to a tab's page session. Both are accessed with JavaScript; neither is a place for secrets. 

// Store a small, non-sensitive preference.
localStorage.setItem("theme", "light");

// Read it later; getItem returns null if missing.
const theme = localStorage.getItem("theme");

// Remove a saved preference.
localStorage.removeItem("theme");

Storage can be unavailable or cleared, and data can be read or changed by scripts running on the same origin. Never store passwords, session tokens, or sensitive personal data there.

14

<canvas> basics

Canvas provides a bitmap drawing surface controlled with JavaScript. It is useful for dynamic graphics, charts, and games, but its drawn pixels do not automatically expose their meaning to screen readers. 

<canvas id="chart" width="320" height="160">
  Monthly rainfall chart: 20, 35, and 28 millimeters.
</canvas>

const canvas = document.querySelector("#chart");
const context = canvas.getContext("2d");
context.fillStyle = "#24584d";
context.fillRect(20, 20, 80, 100);

Provide equivalent text or a data table for meaningful canvas content. Set intrinsic width and height so the drawing surface has a predictable coordinate system.

15

SVG basics

SVG is a resolution-independent vector format that describes shapes and paths. Use an external SVG with <img> for a simple graphic, or inline SVG when individual shapes need styling or interaction. 

<svg viewBox="0 0 100 100" role="img"
  aria-labelledby="sun-title">
  <title id="sun-title">Sun</title>
  <circle cx="50" cy="50"
    r="30" fill="gold"/>
</svg>

Give informative graphics an accessible name. If an SVG is decorative, hide it from assistive technology appropriately. Keep complex interactions keyboard accessible.

16

Progressive enhancement

Build the core experience with semantic HTML first, make it readable with CSS, then add JavaScript as an enhancement. This gives the page a useful baseline on more devices and when scripts fail or load slowly. 

<!-- Core navigation works as ordinary links. -->
<nav aria-label="Sections">
  <a href="#contact">Contact</a>
</nav>

<!-- The contact destination exists even without JavaScript. -->
<section id="contact">...</section>

Do not make essential content depend on a script that might not run. When an enhancement is interactive, provide a fallback or a clear unavailable state.

17

Performance-friendly HTML

Help browsers fetch and lay out resources efficiently. Include image dimensions, use responsive images, and lazy-load offscreen media. Do not lazy-load the main image likely to appear immediately when the page opens. 

<img src="images/bench-800.jpg"
  srcset="images/bench-400.jpg 400w, images/bench-800.jpg 800w"
  sizes="(max-width: 600px) 100vw, 800px"
  width="800" height="533"
  loading="lazy"
  alt="A wooden bench beneath an apple tree">

<script src="app.js" defer></script>

Use defer for scripts that need the document parsed first. Measure before optimizing, and avoid preloading many resources because they compete for bandwidth.

Build for real browsers and real people

Start with semantic markup, then verify structure, keyboard use, screen-reader output, fallbacks, and loading behavior. Advanced HTML is mostly careful choices, not extra tags.
