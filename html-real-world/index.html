Level 4 / Real-world HTML

From markup to useful pages.

Ten small project briefs to help turn HTML skills into real pages. Start with the content and structure, then add CSS, images, and behavior where they improve the experience.

How to use theseEach snippet is a starting point for the project's main content, not a complete website. Put it inside a full HTML document and adapt the content to a real audience.
  • Level 1: HTML Basics
  • Level 2: Intermediate HTML
  • Level 3: Advanced HTML
01

Build a personal profile page

Goal: introduce one person, their interests, and a way to contact them. Use one clear main heading, a short biography, and useful links. 

<main>
  <article>
    <h1>Jordan Lee</h1>
    <img src="images/jordan.jpg"
      alt="Jordan Lee outdoors beside a trail">
    <p>I design small, accessible websites in Seattle.</p>
    <h2>What I enjoy</h2>
    <ul><li>Hiking</li></ul>
  </article>
</main>

Use an image only if it adds context, and write alt text that describes what matters in that context.

02

Build a resume / CV

Goal: make qualifications easy to scan. Organize experience, education, and skills under descriptive headings. Use lists for responsibilities and dates for time periods. 

<section aria-labelledby="experience-title">
  <h2 id="experience-title">Experience</h2>
  <article>
    <h3>Web designer, Northwind Studio</h3>
    <p><time datetime="2022-04">April 2022</time>–Present</p>
    <ul><li>Created accessible page templates.</li></ul>
  </article>
</section>

Keep dates honest and consistent. If you offer a downloadable PDF, also make the HTML page readable and usable on its own.

03

Build a registration form

Goal: collect only the information the service needs. Label every control, group related choices, explain required fields, and make errors clear. 

<form action="/register" method="post">
  <label for="email">Email address</label>
  <input id="email" name="email"
    type="email" autocomplete="email" required>
  <button type="submit">Create account</button>
</form>

HTML provides basic browser validation, but registration needs a secure server endpoint, server-side validation, and a safe approach to passwords and personal data.

04

Build a restaurant website

Goal: help visitors decide where and when to eat. Put the restaurant name, location, hours, menu, and reservation/contact details where people can find them. 

<main>
  <h1>Juniper Table</h1>
  <p>Seasonal cooking in the heart of town.</p>
  <section aria-labelledby="hours-title">
    <h2 id="hours-title">Hours</h2>
    <p>Tuesday–Sunday, 5–10 pm</p>
  </section>
  <address>14 Market Street, Portland</address>
</main>

Keep hours, address, prices, and reservation details current. Use a real menu and clear dietary information instead of relying on text embedded in images.

05

Build a blog page

Goal: present a post and help readers discover related writing. Each post should have a meaningful title, author/date details, readable sections, and links with descriptive text. 

<article>
  <header>
    <p>Field Journal</p>
    <h1>Starting a balcony garden</h1>
    <p>By Sam Chen ·
      <time datetime="2026-05-12">May 12, 2026</time>
    </p>
  </header>
  <p>Begin with the light your balcony receives...</p>
  <h2>Choose a few reliable plants</h2>
</article>

For a blog index, use a list of article previews that link to full posts. Keep the page title and each post title distinct.

06

Build a product page

Goal: give shoppers enough accurate information to compare and decide. Include the product name, useful images, price, options, availability, and a clear purchase action. 

<main>
  <article>
    <h1>Field Notebook</h1>
    <p>Recycled paper, 160 pages, A5 size.</p>
    <p><data value="18.00">$18.00</data></p>
    <form action="/cart" method="post">
      <input type="hidden" name="product" value="field-notebook">
      <button type="submit">Add to cart</button>
    </form>
  </article>
</main>

A real cart requires server-side product and price checks. Never trust a price or product identifier just because it came from a form.

07

Build a portfolio

Goal: show a focused selection of work and explain your role in each project. Make project previews link to case studies, and include outcomes or decisions rather than a wall of images. 

<section aria-labelledby="work-title">
  <h2 id="work-title">Selected work</h2>
  <article>
    <h3><a href="projects/library.html">Library wayfinding</a></h3>
    <p>I redesigned the library's mobile navigation...</p>
  </article>
</section>

Choose real, representative work and credit collaborators. Make contact information easy to find without exposing details you do not want public.

08

Build a landing page

Goal: help one audience take one primary action. State the offer clearly, explain important details, and make the next step easy to identify without misleading claims. 

<main>
  <section aria-labelledby="event-title">
    <p>Community workshop · June 18</p>
    <h1 id="event-title">Make a small garden thrive</h1>
    <p>A hands-on afternoon for first-time growers.</p>
    <a href="#registration">Reserve a place</a>
  </section>
</main>

The action should lead somewhere real. If it is a form, make the required information, privacy expectations, and submission result clear.

09

Build a multi-page website

Goal: divide a larger site into pages with clear responsibilities and consistent navigation. Use ordinary links with relative paths, and give every page a unique title and main heading. 

site/
├── index.html
├── about.html
├── contact.html
├── css/
│   └── site.css
└── images/
    └── studio.jpg

<!-- From about.html, link to another page -->
<a href="contact.html">Contact</a>

<!-- From a page in a subfolder, go up one level -->
<link rel="stylesheet" href="../css/site.css">

Keep navigation labels consistent, verify every path after moving files, and make it possible to reach the main sections without relying on JavaScript.

10

Make pages accessible and SEO-friendly

Goal: make content understandable, discoverable, and usable by people with different devices and abilities. Accessibility and SEO both benefit from clear content and a well-organized document.

  • Set the document language and write a unique, useful page title.
  • Use one clear main heading, meaningful subheadings, and semantic landmarks.
  • Give form fields labels, images useful alternatives, and links descriptive text.
  • Check keyboard operation, visible focus, color contrast, and mobile layout.
  • Validate the HTML, test links, and keep metadata accurate.
<body>
  <a class="skip-link" href="#main">Skip to main content</a>
  <header>...</header>
  <nav aria-label="Main navigation">...</nav>
  <main id="main">...</main>
  <footer>...</footer>
</body>

Automated checks help catch issues, but they cannot replace keyboard testing, content review, and testing with assistive technology.

Choose one project and finish it

Write the content first, build a semantic HTML skeleton, check the links and labels, then add styling and interaction. A small finished page teaches more than ten unfinished templates.
