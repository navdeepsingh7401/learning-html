Level 2 / Intermediate HTML

Give your pages more structure.

Build on the basics with data tables, usable forms, semantic page regions, media, and the paths that connect files in a project.

Before you beginThese examples show HTML structure. Forms need a server or service to process submissions, and media examples need matching files in your project.
01

Tables

Use a table for information arranged in rows and columns, such as a schedule or comparison. Do not use tables to arrange the overall layout of a page; CSS layout tools are better for that.

A table is created with <table>. Its rows, headings, and data cells go inside it.

02

Table headings, rows, and cells

<tr> creates a table row, <th> a header cell, and <td> a data cell. Group header and body rows with <thead> and <tbody>; add a <caption> to describe the table. 

<table>
  <caption>Weekly garden tasks</caption>
  <thead>
    <tr>
      <th scope="col">Day</th>
      <th scope="col">Task</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Monday</th>
      <td>Water seedlings</td>
    </tr>
  </tbody>
</table>
Rendered table
Weekly garden tasks
Day Task
Monday Water seedlings

The scope attribute associates each header with its row or column, which helps people using screen readers.

03

Forms

A form collects information from a visitor. Put related controls inside <form>. The action tells the browser where to send the data, and method sets how it is sent. 

<form action="/signup" method="post">
  <!-- Form controls go here -->
  <button type="submit">Sign up</button>
</form>

This example needs a real /signup endpoint to receive submissions. HTML alone does not store or email the data.

04

Input types

The type attribute changes how an input works and what keyboard or validation the browser provides. Common types include text, email, password, number, date, file, and submit. 

<input type="email" name="email">
<input type="date" name="start-date">
<input type="file" name="photo">

For passwords and uploaded files, handle data securely on the server and use HTTPS. A password input only hides characters on screen; it does not encrypt the value.

05

Labels and placeholders

A <label> names a control. Connect it to the control's unique id with the label's for attribute. Clicking the label then focuses or toggles its control. 

<label for="full-name">Your name</label>
<input id="full-name" name="name"
  type="text" placeholder="e.g. Alex Kim">

A placeholder is a short hint inside an empty control. It disappears when someone types, so it should not replace a visible label or carry essential instructions.

06

Radio buttons and checkboxes

Radio buttons let someone choose one option from a group. Give options in the same group the same name. Checkboxes are for independent choices; a person can select several. 

<p>Choose a delivery time:</p>
<label>
  <input type="radio" name="delivery" value="morning">
  Morning
</label>
<label>
  <input type="checkbox" name="updates" value="yes">
  Send me updates
</label>

Every choice needs a text label. Add checked only when a default selection is genuinely appropriate.

07

Select and textarea

Use <select> for a menu of choices and put each option in an <option>. Use <textarea> for multi-line text; its starting dimensions use rows and cols. 

<label for="topic">Choose a topic</label>
<select id="topic" name="topic">
  <option value="plants">Plants</option>
  <option value="tools">Tools</option>
</select>
<label for="message">Message</label>
<textarea id="message" name="message" rows="4"></textarea>
08

Form validation attributes

HTML can check common input rules before submission. required demands a value; minlength and maxlength limit text length; min and max limit numeric or date values; type="email" checks for an email-shaped value. 

<label for="email-address">Email address</label>
<input id="email-address" name="email"
  type="email" required>
<label for="age">Age</label>
<input id="age" name="age"
  type="number" min="13" max="120">

Browser validation improves convenience, but it can be bypassed. Always validate submitted data on the server too.

09

<div> and <span>

<div> is a generic block container; <span> is a generic inline container. Use them when you need a hook for CSS or scripting and no more meaningful HTML element fits. 

<div class="notice">
  <p>Water the <span class="highlight">new seedlings</span> today.</p>
</div>

If an element has a specific meaning, such as <nav> or <article>, choose that instead of a generic <div>.

10

Semantic HTML

Semantic HTML uses elements that describe the purpose of their content. A <button> is for an action; a <nav> is for navigation. Clear semantics improve accessibility, search understanding, and maintainability.

Choose an element for what the content means, not how you want it to look. Use CSS to change appearance without changing meaning.

11

Page landmarks

These elements describe common regions of a page. Use each for its purpose; a page can have multiple <section> or <article> elements, but usually has one main <main> region.

<header> introductory content for a page or region

<nav> a group of navigation links

<main> the page's primary content

<section> a themed section, usually with a heading

<article> self-contained content that can stand alone

<aside> related, secondary content

<footer> closing information for a page or region 

<header><h1>Garden Journal</h1></header>
<nav aria-label="Main navigation">...</nav>
<main>
  <article>...</article>
  <aside>Related reading...</aside>
</main>
<footer>Contact and copyright...</footer>
12

Audio and video

Use <audio> or <video> with the controls attribute so visitors can play, pause, and adjust playback. A nested <source> gives the browser a file and media type; fallback text helps when media is unsupported. 

<audio controls>
  <source src="media/birds.mp3" type="audio/mpeg">
  Your browser cannot play this audio.
</audio>

<video controls width="640"
  poster="images/garden-preview.jpg">
  <source src="media/garden.mp4" type="video/mp4">
  <track kind="captions" src="media/garden-en.vtt"
    srclang="en" label="English">
  Your browser cannot play this video.
</video>

Provide captions for video with speech, and make sure media has suitable alternatives. The example files must exist at those paths.

13

<iframe>

An iframe embeds another webpage inside yours. Give it a descriptive title, set reasonable dimensions, and only embed content you trust. The external site may apply its own privacy and security rules. 

<iframe
  src="https://www.youtube.com/embed/VIDEO_ID"
  title="A short tour of the garden"
  width="560" height="315"
  loading="lazy"
  allowfullscreen></iframe>

Replace VIDEO_ID with a real video's embed ID. For embeds that do not need scripts or forms, consider a carefully configured sandbox attribute.

14

HTML entities

Entities let you write characters that HTML would otherwise treat as markup, or characters that are awkward to type. They begin with & and end with ;.

&amp; displays as &

&lt; displays as <

&gt; displays as >

&quot; displays as "

For example, to show the text <p> on a page instead of creating a paragraph, write &lt;p&gt; in your HTML.

15

id and class

id identifies one unique element on a page. It can be a link target or a CSS/JavaScript hook. class groups elements that share a style or behavior; multiple elements can share a class, and one element can have several classes. 

<h2 id="spring">Spring plants</h2>
<p class="note highlighted">Plant after the last frost.</p>
<a href="#spring">Jump to spring plants</a>

IDs must be unique within the document. Class names are case-sensitive and should describe a useful role, not a temporary visual detail.

16

File paths and folder structure

Keep related files in clearly named folders. A path tells the browser where a file lives relative to the current page, or at an absolute web address. 

my-site/
├── index.html
├── html-basics/
│   └── index.html
├── html-intermediate/
│   └── index.html
├── images/
│   └── garden.jpg
└── media/
    └── birds.mp3

Relative path examples

From the top-level index.html, link to the beginner lesson with html-basics/index.html. From inside html-intermediate/index.html, go up one folder with ../, then into the basics folder: ../html-basics/index.html.

From the intermediate page, an image in the shared images folder is ../images/garden.jpg. A file in a child folder uses its folder name, such as media/birds.mp3 when the media folder is beside the current page. 

<!-- Link between the two lesson folders -->
<a href="../html-basics/index.html">Review HTML basics</a>

<!-- Image in a shared sibling folder -->
<img src="../images/garden.jpg"
  alt="A garden in spring">

Paths are written from the file containing the link. Use forward slashes (/), keep capitalization consistent, and avoid spaces in file and folder names when you can.
